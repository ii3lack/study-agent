# 上下文压缩（Compaction）设计 Spec

> **状态**：设计已讨论定型，待实现（回家继续）。
> **前置**：滑动窗口已完成（`src/agent/context.py` 的 `window_for_api`，非破坏性、配对安全）。

## 背景与问题

- 上下文每轮**全量重发**，累计成本随轮数**平方增长**。
- 第一刀"滑动窗口"已落地，但它会**遗忘**：旧轮次直接滑出窗口，agent 丢失早期关键信息。
  - 已亲测：长会话里先告诉它"我叫小明、预算 5000"，窗口滑掉后问它，**答不上 / 瞎编**。
- **第二刀目标**：把"丢"换成"**浓缩地记着**"——旧轮次压缩成一段摘要，上下文照样被摁住，但要命的信息活在摘要里。

## 目标形状

```
[ system ]  +  [ 旧轮次的摘要 ]  +  [ 近期若干轮 · 逐字保留 ]
   地基          浓缩的"记忆"           热乎的、要精确的细节
```

## 已定的设计决策

### 1. 缓存友好放置（本设计的关键）

- 摘要**紧跟 system**，作为**稳定前缀**；近期对话追加在**尾部**（易变）。
- 两次重摘之间，`[system + 摘要]` **冻结** → 缓存命中；只有重摘那一下前缀才变。
- **重摘越不勤，缓存越稳**。
- 对比滑动窗口：窗口每轮从 system 后面滑掉旧轮，前缀每轮都变、缓存每轮都死。**压缩反而比窗口更省缓存**——这是"压缩 vs 缓存"张力的两全解。

### 2. 触发与阈值

- **环境变量 `CONTEXT_WINDOW`** 表示模型上下文大小（`100k` / `1M` 等）——预算**模型感知**，不写死。
- **阈值 25%**：上下文超过窗口的 25% 即触发摘要。
- **安全阀**：若摘要后仍超 25%（信息太密、压不进去），把阈值升到 **50%**，避免过度压缩导致失真。
- ⚠️ 单位注意：`estimate_context_tokens` 数的是**字符**，`CONTEXT_WINDOW` 是 **token**，二者粗对齐。学习够用；真要精确，日后换真 tokenizer。

### 3. 存储（非破坏性 + 溯源）

- **`index.json`**：逐字全史，**不动**（原始对话真相）。
- **`summary.json`**：摘要内容 **+ 其原始出处（溯源）**。
- 溯源是为将来留口子：让"摘要模型"回查原文、动态精修摘要（**分层 / 自适应摘要**的高级形态）。

### 4. 新能力 `summarize_messages(messages, client) -> str`

- 这是**第一次"用 LLM 管 LLM 自己的记忆"**——模型不再回答用户，转而替 agent 压缩记忆。这个范式（LLM-as-memory-manager）往后摘要 / 长期记忆 / 子代理都会复用。
- **摘要 prompt 工程**：叮嘱模型"保住关键事实 / 用户偏好 / 未决事项，扔掉寒暄与冗余"。prompt 质量直接决定摘要质量。

## ⏳ 待定（回家先答这颗螺丝）

**边界标记**：runner 每轮拼 `[system + 摘要 + 近期]` 时，**怎么知道哪些消息已被摘要覆盖、哪些还是逐字近期？**

- 候选：消息**下标** / message **id** / **时间戳**。
- 约束：消息当前**没有 id**；**下标会随截断 / 重排漂移**。需要选最稳的那个。
- 它决定：`summary.json` 里记什么、runner 怎么切分"已摘要 vs 近期"。

## 实现子步骤

1. **定边界标记**（先答上面那颗螺丝）。
2. `summarize_messages` + 摘要 prompt（配 **FakeClient** 即可测，不烧真 token）。
3. 摘要的存 / 取（`summary.json` + 溯源 + 边界标记）。
4. 组装 `[system + 摘要 + 近期]` + 阈值触发 / 升级逻辑。
5. 接入 runner（配合 / 替换窗口）+ 持久化。
6. **真机验证**：长会话恢复后，早期关键信息应活在摘要里——再问"我叫什么 / 预算多少"，**应答得上**。
